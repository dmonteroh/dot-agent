# runtime.sh

Shared Bash primitives for verification and checkpoint bookkeeping. This file is sourced by managed helpers and installs no traps. It is not an agent-facing command.

`da_root` resolves a physical project root. `da_node_dir` resolves its physical node. A `.agent` that is a symlink is accepted only when it resolves to a directory named `.agent` that holds `purpose.md`, in a checkout of the same Git repository (the same `git rev-parse --git-common-dir`). That is a shared node, as an orchestrator links it into worker worktrees. Any other link is refused, so a stray link cannot send node writes or private state into another project or into a directory that is not a node. A non-Git root never shares a node. `da_node_shared` tells whether a root's `.agent` is such a link.

`da_state_dir` uses `.state` inside the physical node, in Git and non-Git nodes, so every checkout sharing a node shares its locks and receipts. Receipts stay bound to the worktree that ran them. Its self-ignore file keeps receipts and locks out of Git. This location works in sandboxes that protect `.git/` from writes.

`da_fingerprint` hashes current inputs without staging files. It includes worktree identity, source content, and index state. Runtime state, session-log output, and generated caches are excluded to keep completion retries stable. With a second argument it also writes, from the same pass, a digest of the tracked and unignored files alone, with no commit and no index in it. Checkpoint compares that one across a commit. Each scan hashes runs of regular files in batches, in their original path order. Filenames with newlines travel as NUL-delimited arguments. A symlink contributes its link text. A tracked path beneath a symlink records that boundary. Every verification and publication step computes its own digest.

`da_refuse <what> <next step> [status]` prints `<script>.sh: <what>. <next step>` on stderr and returns the status, 1 by default. `checkpoint.sh`, `log.sh`, `memory.sh`, and `learn.sh` end every refusal through it, and `tests/refusals-v63.sh` refuses one without a next step. The message is one line with the next step last, because callers pipe helpers through `tail`, and a second line can be cut from its first. Another script adopts the helper when its messages are next edited.

`da_lock` and `da_unlock` serialize cooperating writers through an ownership record. An unknown or live owner is not a stale lock. A lock whose owner is not yet recorded, or that is released while being checked, counts as held. A dead owner's lock is recovered only while it still names that owner, so a lock released and taken again by another writer during the check is left alone. `da_lock_wait` retries `da_lock` while the lock is held, for at most `DA_LOCK_WAIT_SECONDS` (default 10), and `checkpoint.sh` and the record writers (`log.sh`, `memory.sh`, `learn.sh`, `absorb.sh`) take their locks through it. These functions do not protect against a separate process that ignores the protocol.

A writer killed while releasing a lock can leave the directory with no owner file, which no dead-owner check can clear. When every attempt of a whole wait finds the directory that way, `da_lock_wait` removes it with `rmdir` and takes the lock, and says so on stderr. `rmdir` removes only an empty directory, so a lock that gained an owner in the meantime stays held. A wait of 0 makes one attempt and never removes one.

`da_doc_citations <doc>` prints what a doc cites, one per line as written: every Markdown link target, then every backticked span. HTML comments are skipped. Fenced code is read like any other line. A link target loses its title and its `#` fragment, and a span loses a trailing `:<line>` or `:<line>-<line>`. It resolves nothing. `links.sh`'s drift check reads stamped docs through it.

Non-Git verification needs declared input roots in `verify.conf`. Ordinary node bookkeeping uses `.agent/` without recursively scanning the user's home. Receipts are local execution records, not an adversarial attestation mechanism.
