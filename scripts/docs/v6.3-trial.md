# Try v6.3 in a project

Use the `feature/v6.3` source checkout. The scripts run locally with Bash, Git, and standard Unix tools. Project checks still use the project's own test and build tools.

## Install or update

From this source checkout, point the command at the project:

```sh
project=/absolute/path/to/project
bash scripts/node.sh update "$project"
```

For a project without `.agent/`, initialize it instead:

```sh
bash scripts/node.sh init --preset software-development --mode track-shared "$project"
```

Choose the tracking mode appropriate for the project. Complete the ordinary bootstrap: purpose, guardrails, quality-bar split, routing, and entry-point mirrors.

An update preserves existing rules, docs, memory, learned records, configuration, and the project-owned check driver. A conflicting custom helper using a new managed name stops migration before changes. Reconcile the shorter preset with local rules. Keep project-specific requirements. Refresh entry points from the matching template in this checkout.

## Configure checks

The starter `.agent/scripts/checks.sh` fails until configured. Replace its body with named project checks. For a project using Node's built-in test runner, a driver can be:

```sh
#!/usr/bin/env bash
set -u
case "${1:-}" in
  test) exec node --test --test-reporter=tap ;;
  lint) exec npm run lint ;;
  *) echo 'Unknown check' >&2; exit 2 ;;
esac
```

Use the project's real commands. Keep the check names in Project guardrails and the entry point. Updates preserve this driver.

The starter `verify.conf` requires a positive TAP count for the `test` check. Use that setting only when the runner emits supported TAP output. Unknown output remains unknown. Configure a project adapter before relying on a test count from another format.

Set `POSITIVE_TEST_CHECKS` to the checks that require a known positive count. Clearing that list accepts successful command exits without proving tests ran. Such receipts still report an unknown count.

## Verify and record

From the target project:

```sh
bash .agent/scripts/checkpoint.sh --checks test \
  --tool <tool> --area payments --summary "Added refund submission"
```

Checkpoint runs verification, diff review, status, and logging. A failed or inconclusive check stops automatic publication. Fix and retry, or explicitly record the failure with `--verification <id> --verify fail`. Repeating the same completed content does not append another entry.

For an earlier verification run:

```sh
bash .agent/scripts/verify.sh run test
bash .agent/scripts/checkpoint.sh --verification <receipt-id> \
  --tool <tool> --area payments --summary "Added refund submission"
```

The receipt ID is in the first command's output. Input changes invalidate it. A bare `--verify pass` cannot replace execution evidence.

Use `--verify n/a` for manual-only work, and `--verify fail` when reporting failed work without a usable receipt. Use `--base <ref>` for committed changes. Add `--node-only` for an explicit node write hidden by Git ignore rules. That flag refuses to skip outstanding product changes.

## Maintenance policy

`checkpoint.conf` defaults to `POLICY=strict`. It blocks actionable status findings. `POLICY=completion` defers size-only maintenance and continues to block structural defects. Informational tool availability does not block either policy.

Review candidates remain advisory. The agent must judge catalog relevance and test adequacy. Scripts cannot decide whether knowledge is durable or whether a source directive represents user intent.

## Finish migration

After reconciliation, run from the source checkout:

```sh
bash scripts/node.sh finalize "$project"
```

Finalization checks node structure. Run the configured project check separately to confirm the driver works. Keep the migration pending while structural repair findings remain.

The version migration creates a backup unless the node uses `track-all`. Preserve that backup and the project's Git diff during the trial. Runtime state and receipts stay outside loaded context, in the worktree's self-ignored `.agent/.state` directory.
