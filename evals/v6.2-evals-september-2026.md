# V6.2 evaluations, September 2026 — what the runs found

A summary of four reports written between 2026-09-03 and 2026-09-05 (`tmp/eval-run-2026-09-03-review.md`, `tmp/v6.2-improvements-2026-09-04.md`, `tmp/v6.2-variants-results-2026-09-04.md`, `tmp/v6.2-round2-2026-09-05.md`). Three runs of the bench in `evals/`, about 560 agent sessions on `claude-sonnet-5`, roughly $125 in total. This file keeps the conclusions; the reports keep the evidence.

## The short version

The corpus does change behavior, in a few specific places, and every one of those places is a rule the model would not apply on its own: no fact restating a canonical source, no learned rule where the routing hook was the defect, no comment narrating the diff, no groom that drops a ticket id. Everything else the model does with a plain instructions file too. What made the corpus better was moving those rules into code. What made it worse was prose: more of it, less of it, or examples that retold the test. The single largest measurement error was teaching to the test, and the single largest cost lever was the number of tool calls, not the number of words.

## What was good

- **The paired design caught its own bugs.** The first run (09-03) reported write-back failing in both arms. Failing identically in both arms is the signature of a grader defect, not a corpus defect, and it was: every node-diff counter had graded an empty diff because of a path prefix. Thirteen harness defects came out of that run and one real result: the canonical-source gate held in the treatment and not in the control.
- **Evidence strings on every record, and records that re-grade without a model.** The prefix bug was found in minutes because the failing record named the path it had seen, and the whole run was re-graded from its directory afterwards.
- **Fixes in code worked where sentences had not.** `memory.sh supersede` turned an assertion that failed in every arm into one that passed in every arm. `log.sh` refusing a summary that names a file or a SHA did the same for the log format. The `GROOM:` line listing the tokens a groom must keep took fact loss from failing in all four baseline runs to passing in all three of the adopted corpus's. Each of these was first tried as a sentence and measured as not applied.
- **Cutting tool calls cut cost with the rules unchanged.** USD per tool call was flat across every corpus size tried, and the harness made three to four times the calls of a plain instructions file, five of them bootstrap reads. One call to load (`status.sh --load`) and one call to finish (`finish.sh`) took calls per session down 27% on both prompt sets, with no assertion regressing. That shape is what shipped.
- **The bench itself is now harder to fool.** A held-out prompt set, a contamination judge, assertion strata, a pooled multi-run control, and a calibrated grading triage were added on 09-05 (see [README](README.md), "Keeping it honest").

## What made it worse

- **Worked examples that retold the evals.** The `examples` variant scored best on 09-04, the only arm with no unique failure. The contamination judge found that 11 of its worked examples describe the same situation as one of the 19 eval prompts, in an invented domain the lexical probe could not see. On the held-out set it was the only arm to score below the base, losing the routing answer and dropping groom content silently.
- **Compressing the prose.** The lean variant halved the always-loaded words and lost exactly the two rules it compressed (the "earns its place" comment list and the name-the-source sentence). Restoring those two and putting lean on the two-call mechanics still lost one repeat each of the same two rules plus the catalog rule. Words that state an admission rule are doing work; words that restate general practice are not.
- **More prose, and more precise prose.** The protocol variant (a phase-gated checklist, 4,437 always-loaded words) cost 36% more per session and moved nothing.
- **One repeat per cell.** The same corpus scored 91.2 to 94.7 across four identical runs; six assertions flipped with nothing changed. Every 09-04 variant delta sat inside that band. Nothing measured at one repeat was a verdict.
- **The eval set measuring itself.** The 09-04 corpus edits were written from this set's failing transcripts. Two assertions turned out to measure prompt wording: the vendor-comment row passes in every arm on the canonical phrasing and fails in every arm on the paraphrase; the supersede "no history" row fails only on the held-out phrasing that hands the session the old value. The first was rewritten to accept a named constant; the second is a prompt to reword.
- **Mechanical groom helpers.** Lossless `distill` and `archive` scripts were used correctly in every groom session and cleared the flags, and the sessions then rewrote the moved text by hand anyway. No measured gain; not merged.
- **A small side effect of the finish call.** Six of 140 two-call sessions answered mid-turn, ran `finish.sh`, and ended with "Done — answered the question and logged the session." The answer reached the user; the final message did not carry it. One sentence in the entry point now says the final message is the report itself.

## How it got confirmed

| Claim | How |
| --- | --- |
| The adopted corpus beats the pre-adoption one | Pooled control of four identical baseline runs (n=4 per assertion), candidates at two repeats, then the adopted tip at three repeats on both prompt sets. Canonical: 93.4% → 96.5% with zero unique failures. Held-out: 96.5% → 97.7%, behavior rows 94.1% → 98.0%. |
| It is the mechanics, not the words | Same rules on the two-call shape: 0.73× the tool calls on the canonical set, 0.63× on held-out. Lean prose on the same mechanics saved 5 more points of USD and lost rules. |
| The gain survives rewording | `evals/heldout.json`: same fixtures and assertion ids, every prompt rewritten after the variants were frozen. Twocall 99.1% → 98.2%; examples 96.5% → 94.7%, below the base. |
| The examples win was contamination | `evals/contamination.py --judge`: 11 matching passages in `variant/examples`, 0 in the base and in every adopted change. |
| It holds on another model | Haiku 4.5, seven-eval subset: twocall 95.0% vs base 90.0%, fewer calls, no regression. |
| The grader is consistent | `evals/triage.py` calibrated against the 09-04 human grades: full agreement except one shape the human had graded both ways; one rule applied since. |
| The three code fixes are the delta | Per-assertion buckets: `date-bumped`, `no-fact-loss`, `source-fixed` moved from 0.00–0.50 to 1.00 in the tooling arm alone; everything else stayed inside the flake band. |

## What to carry forward

The pooled control for the next round is the adopted corpus at three repeats (`~/eval-runs/base3-canon`, `base3-heldout`). Run the contamination judge on any branch before believing its delta. Grade fact loss under one rule: a value the reply names as contradicting the repository may go, anything dropped silently fails. Treat a delta under two assertions as noise until repeated. And when a rule is not being applied, look for the script that could refuse the wrong shape before rewriting the sentence.
