## Root cause: baseline is unbuildable, not merely unfavorable

Every baseline `run-meta.json` in both workspaces records `"status": "fixture_build_failed"` and `"void": true`, with the same `fixture-build.txt` line:

```
node.sh: unknown flag: --indexes
...
fixtures.sh: node.sh init failed
```

The harness's `fixtures.sh` passes `--indexes` (the F20a index-mode flag) unconditionally when building a fixture. That flag does not exist at `48d9bc03`, which predates F20a's introduction of `--index-mode` / `--indexes`. Every baseline fixture build fails before an agent ever runs. This is not a behavioral regression the corpus is measuring — it is a harness/baseline-SHA mismatch that makes a paired comparison against this specific baseline commit structurally impossible with the current `fixtures.sh`. A baseline that predates the flag it's unconditionally passed cannot be compared this way; either the baseline needs to move to a revision that supports `--indexes`, or `fixtures.sh` needs a compatibility path for pre-F20a baselines. That decision is out of this report's scope.

Confirmed directly: `grep`ing every `arm-map.json`-labeled `baseline` run id for a `grading.json` in either iteration-1 workspace returns zero hits. Zero baseline assertions were ever graded.

## What `evals/rollup.py` reported

Per `evals/HOWTO.md` §4 ("Roll it up"):

```
python3 evals/rollup.py "<claude iteration-1>"
python3 evals/rollup.py "<codex iteration-1>"
```

First pass on both directories refused with the same class of error: manual (`grade: "manual"`) assertions were left ungraded (`passed: null`) by the live sessions — `comments-feature/vendor-constraint-kept` (claude) and `groom-acts-on-flags/no-fact-loss` (codex), then five more per agent once those two cleared. Per HOWTO's instructions ("open outputs/, read the artifacts, fill in `passed` and a quoted `evidence` string by hand — blind to which run is which arm"), this pass graded all 13 ungraded manual assertions found across both workspaces (7 unique assertion ids × the agents/evals they appeared in), reading only the fixture diffs and session transcripts, with `arm-map.json` not consulted for content (only used afterward to label rows). All 13 graded pass. Full assertion text, evidence quoted, and the verdict for each is recorded in that assertion's `grading.json` under the iteration workspace listed above (not reproduced here — see "Redaction and reproducibility" below).

After that, both directories terminated at the same class of failure, this time unrecoverable by grading:

```
$ python3 evals/rollup.py ".../claude/iteration-1"
rollup.py: bootstrap-complete/memory-index-read was graded in ['candidate'] only — an unpaired
assertion has no delta

$ python3 evals/rollup.py ".../codex/iteration-1"
rollup.py: bootstrap-complete/memory-index-read was graded in ['candidate'] only — an unpaired
assertion has no delta
```

`rollup.py` requires every graded assertion to be paired across both arms (line ~344–348 of `evals/rollup.py`). Since the baseline arm never produced a single `grading.json` in either workspace, **every** assertion in **every** eval is candidate-only, not just `bootstrap-complete`'s. `rollup.py` dies on the first one it reaches alphabetically; excluding it with `--exclude-eval` would only move the same failure to the next assertion, and so on through the full set — `--exclude-eval` exists for the four generated-only evals HOWTO documents, not for a wholesale missing arm. This tool cannot produce a rollup table, a discriminating/non-discriminating/regression/unstable classification, or a `concentration_pct_of_delta` figure from this data, and neither can any equivalent hand computation: a delta needs two points, and there is only one.

## Bottom line

- **F9's acceptance criteria are not met by this run.** No release claim here traces to a versioned, paired delta; no interval accounts for scenario clustering (repeats=1, and there is no second arm to cluster against regardless); several unmeasured/unsupported paths (7 of 19 declared evals) remain explicitly unvalidated rather than silently dropped.
- **Nothing here is a regression check.** Zero baseline data exists to regress against — the baseline SHA cannot build a fixture under the current harness. This is a harness/baseline-compatibility defect, not a candidate defect, and not evidence the candidate held or improved anything relative to `48d9bc03`.
- **What can be said:** on the 12 evals with candidate data, claude passed 31/33 graded assertions and codex passed 26/29, all software-development preset, repeats=1, single-arm (no control). 5 auto-graded assertions failed outright (2 claude, 3 codex) and are worth triage on their own terms, independent of any baseline comparison.
- **Before F9 can be re-attempted:** either move the declared baseline to a revision `fixtures.sh` can build, or give `fixtures.sh` a compatibility path for pre-F20a baselines; finish the four void `retro-source-gate` invocations; and locate or re-run the three `continuity-*` evals and the three never-recorded evals so the full 19-eval set is actually covered.
